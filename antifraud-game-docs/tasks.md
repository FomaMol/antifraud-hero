# Антифрод Hero — Задачи для разработчика

## Контекст

Пиксельная браузерная игра (point & click) в стиле Papers, Please. Игрок проверяет входящие кейсы (сообщения, транзакции) и выносит вердикт: легитимно или мошенничество. Кейсы подаются по порядку. Конечная игра: прошёл все уровни → поздравление.

**Платформа:** Web (браузер) | **Стиль:** Pixel art | **Контент:** Data-driven (конфиги) | **Локализация:** русский + английский

## Зафиксированный MVP-объём

**Структура игры:** 3 уровня по 7 кейсов. Всего 21 кейс.

**Типы кейсов:**
- Фишинг "от банка" — домен-клон, запрос данных
- "Мам, я в беде" — срочность, перевод на чужую карту
- "Гос. штрафы" — давление, оплата на личный номер
- Ложная реклама — обещания богатства, срочность
- Настоящие обращения — выглядят подозрительно, но легитимны

**Прогрессия табов:**
- Уровень 1: Сканер ссылок
- Уровень 2: + Проверка получателя/контакта
- Уровень 3: + Официальная база

**Механика табов:** казуальная — нажал "Проверить" → автоподсветка красным/зелёным + поп-ап "Совпадение"/"Несовпадение"

**Обязательные экраны MVP:** загрузка, главное меню, "Как играть", рабочий стол, поп-ап результата кейса, итоги смены, финальное поздравление.

**Настройки в MVP:** звук, музыка, язык.

**Локализация в MVP:** русский и английский, по умолчанию русский.

**Кнопка "Уточнить":** бустер-подсказка (не вердикт). Ограниченное кол-во за уровень. Подсвечивает подозрительные элементы прямо в кейсе, после чего игрок всё равно выбирает "Подтвердить" или "Заблокировать".

**При "Попробовать ещё":** кейсы уровня перемешиваются, счётчик "Уточнить" сбрасывается.

## Спринт 1 (Неделя 1): Каркас + Core Loop

---

### T-1.1 Настройка проекта

**Описание:** Создать проект, настроить структуру папок (экраны, компоненты, конфиги, ассеты, локализация), настроить сборку (dev + prod). Тестовый билд должен открываться в браузере.

**Критерий готовности:** пустой проект собирается и открывается в браузере.

---

### T-1.2 Экраны навигации: загрузка, меню, туториал

**Описание:** Реализовать три экрана до геймплея:
- **Загрузка** — логотип по центру, индикатор загрузки, автопереход в меню после загрузки ассетов
- **Главное меню** — заголовок "Антифрод Hero", кнопки "Начать смену" (→ туториал при первом запуске или сразу в игру), "Как играть" (→ туториал), фон-placeholder
- **Туториал "Как играть"** — 3 шага с иконками-плейсхолдерами: "Открой кейс" → "Проверь факты инструментами" → "Вынеси вердикт". Кнопка "К работе" → переход на рабочий стол (уровень 1)

**Критерий готовности:** все три экрана отображаются, навигация между ними работает.

---

### T-1.3 Контентный движок: формат конфигов и парсинг

**Описание:** Спроектировать и реализовать формат конфиг-файлов для кейсов и уровней.

**Структура конфига кейса:**
- `id` — уникальный идентификатор
- `type` — тип (phishing / fake_gov / fake_ad / fake_relative / legit)
- `category_label` — краткое описание для карточки ("SMS" / "Email" / "Перевод")
- `message_text` — текст входящего сообщения/транзакции
- `metadata` — объект с полями: sender, phone/email, link, amount, recipient, ip (каждое поле опционально)
- `is_fraud` — true/false
- `correct_verdict` — "approve" / "block"
- `tabs_data` — объект с данными для каждого таба:
  - `link_scanner` — { real_url, alert_text, is_suspicious }
  - `contact_check` — { real_name, match_result, alert_text }
  - `official_db` — { record_exists, alert_text }
- `hint_text` — текст подсказки при использовании "Уточнить"
- `explanation` — текст разбора после вердикта

**Структура конфига уровня:**
- `level_id`
- `level_name`
- `cases` — массив id кейсов (порядок при первом прохождении; при "Попробовать ещё" — перемешиваются)
- `available_tabs` — массив доступных табов
- `hints_count` — кол-во использований "Уточнить"
- `pass_threshold` — минимум правильных для прохождения

Реализовать загрузку и парсинг конфигов. Создать 2–3 тестовых кейса (placeholder-контент) для разработки.

**Критерий готовности:** конфиги загружаются, данные кейсов и уровней доступны в коде.

---

### T-1.4 Рабочий стол: layout + очередь кейсов

**Описание:** Основной экран геймплея с фиксированным layout и навигацией по кейсам.

**Layout:**
- **Левая колонка (очередь кейсов):** список карточек (номер кейса, иконка типа placeholder, `category_label`). Текущий кейс подсвечен, решённые помечены (галочка/крестик). Кейсы доступны по порядку — нельзя перескочить вперёд.
- **Центр (окно "Входящее"):** основной текст сообщения (`message_text`) + блок метаданных (отправитель, контакт, сумма/получатель, ссылка — только те поля, которые есть в конфиге).
- **Правая колонка (табы):** заглушки табов (заголовки без функциональности — реализуются в спринте 2).
- **Нижняя панель:** кнопки "Подтвердить" / "Заблокировать" / "Уточнить" + счётчик "Подсказки: N".

**Навигация по кейсам:**
- При старте уровня — загрузить кейсы из конфига по порядку
- Клик по кейсу → отображение в центральном окне
- Индикатор прогресса: "кейс 3/7"
- После вердикта — автопереход к следующему кейсу
- После последнего кейса → экран "Итоги смены"

**Критерий готовности:** экран отображает layout со всеми зонами, данные подставляются из конфига, можно последовательно проходить кейсы от первого до последнего.

---

### T-1.5 Панель вердикта + поп-ап результата

**Описание:** Кнопки принятия решения, бустер "Уточнить" и фидбек после каждого вердикта.

**Панель вердикта:**
- **"Подтвердить"** — игрок считает кейс легитимным
- **"Заблокировать"** — игрок считает кейс мошенничеством
- **"Уточнить"** (бустер):
  - Счётчик оставшихся использований
  - При нажатии: подсвечивает подозрительные элементы прямо в кейсе (из `hint_text`)
  - Не является вердиктом — после подсказки игрок всё равно жмёт "Подтвердить" или "Заблокировать"
  - Когда использования кончились — кнопка неактивна (серая)
- После вердикта — сравнить с `correct_verdict`, подсчитать результат
- Заблокировать повторное нажатие до закрытия поп-апа

**Поп-ап результата кейса:**
- Поп-ап поверх рабочего стола (затемнение фона)
- Заголовок: "Верно!" (зелёный) или "Ошибка!" (красный)
- Текст объяснения из `explanation`
- Кнопка "Следующий кейс" → закрывает поп-ап, переход к следующему
- Если последний кейс — кнопка "Результаты смены" → переход на экран итогов

**Критерий готовности:** все три кнопки работают, "Уточнить" подсвечивает элементы в кейсе и тратит использование, после вердикта виден поп-ап с результатом и объяснением.

## Спринт 2 (Неделя 2): Табы + уровни + контент

---

### T-2.1 Система табов

**Описание:** Реализовать механику всех трёх табов в правой колонке как единую систему.

**Общая механика:**
- Правая колонка содержит переключаемые табы (заголовки-кнопки сверху)
- Показывать только доступные табы на текущем уровне (`available_tabs`). Недоступные — скрыты или серые с замком.
- В каждом табе: кнопка "Проверить" и область для результата
- По нажатию "Проверить": краткая анимация (0.5–1 сек) → в центральном окне соответствующее поле метаданных подсвечивается красным (ALERT) или зелёным (OK) → в табе появляется текст результата + бейдж OK/ALERT
- "Проверить" неактивна после использования (нельзя нажать повторно на том же кейсе)
- При переключении на новый кейс — табы сбрасываются

**Tab 1 — Сканер ссылок** (доступен с уровня 1):
- Если в кейсе есть ссылка — "Проверить" активна; если нет — "Нет ссылок для проверки"
- Результат из `tabs_data.link_scanner`: реальный URL (`real_url`), текст алерта (`alert_text`), бейдж ALERT/OK по `is_suspicious`
- Подсветка поля "ссылка" в центральном окне

**Tab 2 — Проверка контакта** (доступен с уровня 2):
- Если есть получатель/отправитель — "Проверить" активна
- Результат из `tabs_data.contact_check`: реальное имя (`real_name`), результат сопоставления (`match_result`), текст алерта, бейдж
- Подсветка поля "получатель"/"отправитель"

**Tab 3 — Официальная база** (доступен с уровня 3):
- Если есть номер постановления/название организации — "Проверить" активна
- Результат из `tabs_data.official_db`: запись существует/нет (`record_exists`), текст алерта, бейдж
- Подсветка соответствующего поля

**Критерий готовности:** табы переключаются, разблокируются по уровням, "Проверить" подсвечивает данные в кейсе и показывает результат для всех трёх типов.

---

### T-2.2 Система уровней + экран итогов + финал

**Описание:** Прогрессия по уровням, экран статистики и финальное поздравление.

**Конфигурация уровней:**
- **Уровень 1** (7 кейсов): табы = [link_scanner]. Простые кейсы (очевидный фишинг).
- **Уровень 2** (7 кейсов): табы = [link_scanner, contact_check]. Средние кейсы.
- **Уровень 3** (7 кейсов): табы = [link_scanner, contact_check, official_db]. Пограничные кейсы.
- При старте уровня: загрузить конфиг, определить доступные табы, загрузить кейсы.
- Хранить прогресс игрока: какой уровень пройден (чтобы при "Начать смену" продолжить с нужного).

**Экран "Итоги смены":**
- Статистика: "Проверено: 7", "Ошибок: N", "Точность: X%"
- Оценка смены: Отлично (все верно или 1 ошибка) / Хорошо (≥ pass_threshold) / Неплохо (близко к порогу) / Плохо (далеко от порога)
- Если ≥ "Хорошо" → кнопка **"Следующий уровень"**
- Если < "Хорошо" → кнопка **"Попробовать ещё"**
  - Кейсы того же уровня перемешиваются в случайном порядке
  - Счётчик "Уточнить" сбрасывается

**Финальный поп-ап:**
- После прохождения уровня 3 — поздравление
- Кнопка "В меню" → возврат на главное меню

**Критерий готовности:** 3 уровня загружаются последовательно, табы открываются по уровням, итоги показывают статистику, "Попробовать ещё" перемешивает кейсы, после уровня 3 — поздравление.

### T-2.3 Контент: 21 кейс (русский)

**Описание:** Написать контент для всех 21 кейса на русском языке в формате конфигов.

**Распределение по типам и сложности:**
- Уровень 1 (7 кейсов, простые): преимущественно фишинг "от банка" и ложная реклама с очевидными признаками + 1–2 легитимных
- Уровень 2 (7 кейсов, средние): "мам я в беде", фишинг с правдоподобным текстом, ложная реклама + легитимные
- Уровень 3 (7 кейсов, пограничные): гос. штрафы, сложные случаи всех типов, больше легитимных — без проверки не ясно

Каждый кейс должен содержать все поля конфига: message_text, metadata, tabs_data, hint_text, explanation.

**Критерий готовности:** 21 кейс в формате конфигов, покрывают все 5 типов, сложность растёт по уровням, данные для табов корректны.

## Спринт 3 (Неделя 3): Локализация, звук, полировка

---

### T-3.1 Локализация (русский + английский)

**Описание:** Вынести все строки в файлы локализации и подготовить английскую версию.

- Все строки UI — в файлы локализации (отдельный файл на каждый язык)
- Контент 21 кейса — отдельные конфиг-файлы на каждый язык (или поля `_ru` / `_en`)
- Переключение языка применяется мгновенно
- По умолчанию: русский

**Критерий готовности:** игра полностью играбельна на обоих языках, переключение работает без перезагрузки.

---

### T-3.2 Настройки + звук

**Описание:** Экран настроек и звуковое оформление.

**Настройки** (доступны из главного меню):
- Переключатель звуков (вкл/выкл)
- Переключатель музыки (вкл/выкл)
- Переключатель языка (русский / английский)
- Сохранение настроек между сессиями (localStorage)

**Звуки и музыка** (ассеты предоставляются отдельно):
- Фоновая музыка (лупится)
- Звук клика по кнопке
- Звук "верно"
- Звук "ошибка"
- Звук нового кейса
- Все звуки учитывают настройку вкл/выкл

**Критерий готовности:** настройки сохраняются, звуки воспроизводятся и отключаются корректно.

**Описание:** Тестирование, багфиксы и подготовка к релизу.

- Фикс найденных багов

**Критерий готовности:** готовый к деплою веб-билд, работает в основных браузерах.
